Grocery Price Checker & Item Selection
Grocery Price Checker
The main window for checking prices. This Displays all of the items that need to be purchased. Items are displayed inside a button that opens the next window that facilitates the scraping tool and also which store will be looked at. Besides the button, once the final selection is made, this window shows the information from the item such as name, weight, price of the package, price per unit, cost using totals from monthly needs of the item, the picture of the item, and the number of packs needed to purchase to fill the scheduled meals within the expiration date time frame.
Items are sorted by Item Category into headers which are collapsable. A search bar at the top allows filtering the results by item name.

Inventory Timeline & Stock Management
Inventory Timeline
This window displays each item’s stock level on a 52‑week grid, showing the planned inventory for every week. Stock levels decrease automatically week by week based on meal plans and the secondary yearly consumption plan.
Items are grouped by category with collapsible headers.
A search box allows filtering by item name.
The Add Purchase button lets the user enter an item and quantity in the search box, then apply that amount to the selected week.
Purchase History opens a window listing all logged stock additions, showing the item, quantity, and date. Each entry has a delete button to reverse the change.
Current View limits the 52‑week grid to only the weeks remaining in the current year.
Item details include the product image, item name, expiration (in weeks), weekly need, and for each of the 52 weeks, both the planned stock value and expiration weeks remaining.
Clicking the displayed weekly need opens a breakdown window showing how the value is calculated: monthly meal plan consumption plus secondary monthly consumption, combined into a total monthly need, then converted using the 4.33 average weeks per month to yield the weekly need.
Implemented in:
* inventoryTimeline.html + inventoryTimeline.js + inventoryTimeline.css (Inventory Timeline window)
* inventoryTimeline.html + inventoryTimeline.js (Add Purchase button, Purchase History view, Current View limiter)
* weeklyNeedDebug.html + weeklyNeedDebug.js (Weekly need breakdown window)

Add Item
This button opens a window where the user can add a new item to be tracked, along with default values provided by the application. The required fields are: Item Name, Current Stock Values, and Item Category. Other fields are pre‑filled with defaults, but the user can override them if needed.
Yearly Need defaults to 0. This links to the secondary consumption plan and is used to calculate yearly, monthly, and weekly needs on the inventory timeline.
Home Unit defines the item’s default unit of measure (default: Oz). This unit is used to normalize store data into a consistent price‑per‑unit across all items.
Volume‑to‑Weight Ratio sets the conversion factor between liquid and weight measurements. The default is 1:1 (1 fl oz = 1 oz, based on water). The user can measure the actual product to determine a more accurate ratio. The app automatically applies this conversion to scraped store data so that pricing is consistent.
Treat as Whole Unit (default: off) determines how inventory is deducted when an item is used. By default, items are reduced only by the exact unit value (e.g., 10 oz from a 12 oz can). When enabled, the system deducts by item count instead, meaning the entire container is removed from stock. For example, if a recipe calls for 10 oz of tomatoes and the item is tracked as a 12 oz can, this setting ensures that one whole can (12 oz) is deducted rather than leaving a partial can in inventory.
Shelf Life (in weeks) sets the expiration period for the item. Default is 2 weeks.
Default Week shows the week the current stock value will be applied to, which defaults to the user’s current week.
Seasons Available lets the user enter ranges (start and end weeks) when the item is in season. Multiple ranges can be added, and each has a remove button to delete it. Season available gates when the items will be possible scheduled meals. When the calendar is built for weeks outside of the season range, the items out of season will not be considered as meals.
Finally, the Commit button saves all the entered information and adds the item to the inventory.
Implemented in: addItem.html + addItem.js

Meal Planner
This button opens the main meal planning window. Here, the app calculates the user’s meal schedule based on selected options. Using a formula referred to as “meal math,” it estimates how much food will be consumed on average and provides that data to other parts of the application.
Meal Math works as follows: it uses the formula below to determine how many times each meal is prepared:
A × (B × C) × 52 = yearly spots for the category
(yearly spots / D) / 12 = monthly spots for a single meal
where:
* A is the number of meals of that category served per day
* B is the number of people eating that category
* C is the number of days per week they eat it
* D is the number of different meals in the category
After this calculation, the meals each user is subscribed to are placed into the calendar, filling the available meal slots.
Implemented in: mealPlanner.html + mealPlanner.js (import logic in mealImport.js)

Open Meal List
This button opens a window where the user can manage meal categories—adding new ones, or editing existing meals and their details.
The window displays all meal categories as buttons. Clicking a category opens its meal list for editing.
At the bottom, there is also a button to add a new meal category.
Within each category, meals are shown under collapsible headers.
Each meal entry begins with a list of users and checkboxes to indicate who is subscribed to that meal.
Next, the meal’s image and name are displayed, along with an edit button to make all fields editable.
When the edit mode is enabled, a box to change the meals recipie book (the headers for this window) is shown.
Flags indicate whether the meal is a prepared meal (more involved than simple assembly) or a prep‑ahead meal (requiring advance preparation).
The weight value determines how often the meal is scheduled relative to other meals with different weights.
A group flag can be set to schedule the meal at the same day and time for all users, if possible. The planner aligns group meals first, then fills in non‑group meals. Users not subscribed to a group meal receive a non‑group meal instead.
Each meal also includes a section listing its ingredients. For every ingredient, the user can enter a name, amount, and cost. The name links to an item tracked in the inventory timeline and tied to grocery price scraper data. The amount reflects an average per user (not exact for each person if multiple users are subscribed). The cost is calculated from the scraper data associated with that ingredient.
The total calculated cost for the meal appears at the end of the entry.
The Add Meal button in the category window opens a form for creating a new meal within that category. The form includes a box for the meal name, an ingredient field with an amount value, and a drop‑down to select the unit of measure. Once data is entered in the first line, a new line appears, allowing multiple ingredients to be added. The selected unit of measure is compared against the item’s home unit of measure to calculate ingredient costs. Options are available to flag the meal as a prepared meal, a prep‑ahead meal, or a group meal. At the bottom, there is also a box to enter which recipe book the meal comes from, used for sorting meals within the category list.
The Remove Meal button enables a deletion mode, adding a delete button next to each meal, which permanently removes it from the app.
Implemented in: mealListSelect.html + mealListSelect.js, mealListView.html + mealListView.js, addMeal.html + addMeal.js

Import Meals
This button allows bulk importing of meal XML lists. The lists must follow a specific format described in the readme file. Clicking the button opens a file browser to select the file, and each meal in the file is then imported.
Each ingredient in the imported meals is added to the inventory with default values. For items missing certain defaults, the app fills them in automatically—for example, assigning the item name, setting the starting quantity to zero, and placing the item in a temporary “Mass Import” category.
