Schema and deduplication insights
* Item-centric consolidation: The numerous scraped_*, selected_*, and final_* keys imply each item tracks scraped options, a chosen product, and a final store separately. Consolidating into items[itemId] = {scraped: [...], selected: {...}, finalStore: ...} removes duplicated name prefixes and simplifies lookups.
* Versioned history: Collections like consumedThisYear, currentStock, and expirationData focus on the same items with temporal data. Representing them as events nested under an items[itemId] record supports versioning (e.g., { purchases: [ {timestamp, qty, store}, ... ] }) and dedupes repeated keys.
* Field overlap among meals: Meal categories reuse identical fields, suggesting a single meals collection with a type attribute rather than separate arrays.
This analysis helps shape a normalized schema with nested, versioned records and clearer separation between item metadata, product options, and consumption events.
