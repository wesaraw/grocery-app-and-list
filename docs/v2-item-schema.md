# V2 Item and Event Schema

This document outlines the normalized schema for the version 2.0 data migration. It consolidates the scattered `final_*`, `selected_*`, and `scraped_*` records into a single `items` collection and captures historical events for each item.

## ItemRecord

`items[itemId]` stores every product by a deduplicated numeric ID derived from the v1 `itemNameMap`.

```ts
interface ItemRecord {
  id: string;              // numeric ID
  name: string;            // human-readable label
  unit: string;            // base unit for stock & consumption
  stock?: Quantity;        // currentStock entry
  scraped: ScrapedProduct[]; // all scraped product options
  selected?: SelectedProduct | null; // chosen product per store
  finalStore?: string | null;       // storeId of the approved option
  purchases: PurchaseEvent[];       // chronological purchase log
  consumption: ConsumptionInfo;    // totals & history
  expiration?: Record<string, number>; // date -> quantity mapping
  seasons?: string[];               // seasonal availability tags
}
```

### Quantity
```ts
interface Quantity {
  amount: number;
  unit: string;
}
```

## Product Details

### ScrapedProduct
Represents a single offer scraped from a store site.
```ts
interface ScrapedProduct {
  storeId: string;
  name: string;
  link: string;
  image?: string;
  price: number;            // numeric price
  pricePerUnit?: number;    // optional unit price
  sizeQty?: number;
  sizeUnit?: string;
  unitQty?: number | null;  // per-unit quantity when applicable
  unitType?: string | null; // e.g. lb, oz
  convertedQty?: number;    // normalized item quantity
  scrapedAt: string;        // ISO timestamp
}
```

### SelectedProduct
Details for the store-specific choice surfaced to users.
```ts
interface SelectedProduct extends ScrapedProduct {}
```

## Event Histories

### PurchaseEvent
```ts
interface PurchaseEvent {
  storeId: string;
  quantity: number; // amount purchased
  unit: string;     // unit of measure
  price: number;    // total price paid
  purchasedAt: string; // ISO date
}
```

### ConsumptionInfo
```ts
interface ConsumptionInfo {
  total: number;        // "consumedThisYear" amount
  unit: string;         // base unit
  history: ConsumptionEvent[]; // from "consumedHistory"
  overrides: Record<number, number>; // week -> adjustment
}
```

### ConsumptionEvent
```ts
interface ConsumptionEvent {
  id: string;      // unique entry id
  date: string;    // local date string
  diff: number;    // amount consumed (+/-)
  week?: number;   // optional week index for overrides
}
```

## Meals

Meal collections from v1 consolidate into a single `meals` array, each tagged with a `type`.
```ts
interface Meal {
  id: string;
  name: string;
  type: string; // breakfast, lunchDinner, etc.
  people: number;
  ingredients: { itemId: string; amount: number; unit: string }[];
  users: string[];
  prepared: boolean;
  totalCost?: number;
}
```

### PreparedMealsCalendar
A calendar mapping of cooking days to meal IDs generated by `generatePreparedMealsCalendar`.
```ts
interface PreparedMealsCalendar {
  [date: string]: { [category: string]: string }; // date -> category -> mealId
}
```

## Validation Notes
- Unknown fields should trigger warnings during migration.
- Numeric fields accept integers or floats; all dates use ISO `YYYY-MM-DD` strings.
- Optional properties may be omitted or set to `null`.
